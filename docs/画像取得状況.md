# 観光画像取得 進捗ドキュメント

最終更新: 2026-05-02

## 1. 目的

本アプリ（`lookup.html` ビジュアル図鑑と `map.html` 都道府県詳細パネル）に、観光地・グルメ・温泉・祭り・世界遺産・国立公園の写真を表示する。「文字情報だけでは観光地のイメージが伝わらない」課題を解消するのが狙い。

## 2. 採用した方針

**Wikidata + SPARQL → Wikimedia Commons** の3段パイプライン。

| 検討項目 | 選択 | 理由 |
|---|---|---|
| 画像源 | Wikimedia Commons | 商用利用可、大量、ライセンス明示 |
| 配信方式 | Commons URL を直リンク | Git容量0、Commons公式が hotlink を許容 |
| ID 解決 | Wikipedia 日本語版 API → P18 (Wikidata) | 日本語名から堅実に Q-ID を解決 |
| メタデータ格納 | カテゴリ別 JSON（`webapp/public/images/*.json`） | osm_pois 方式踏襲、遅延ロード可 |
| 既存YAML改修 | しない | 画像は派生データ、ソース・オブ・トゥルースを汚さない |
| Python依存 | 標準ライブラリのみ | `requests` 不要、`urllib` で完結 |

### 検討して**採用しなかった**もの

| 案 | 不採用の理由 |
|---|---|
| ローカルにDLしてキャッシュ | 30〜50MB級になり Git 肥大化。Commons hotlink で十分 |
| Wikipedia pageimages フォールバック | ja-Wikipedia 直アップ画像（Fair Use）が混入し商用NGリスク |
| Pixabay/Pexels | 日本固有名詞のヒット率が低い（英訳キーワード必要） |
| UEC FOOD 100/256 | **非商用研究のみ** で完全に NG |
| ぱくたそ・写真AC | API なし、グッズ化禁止条項で運用リスク |

## 3. パイプライン

### Stage 1: Q-ID 解決（Wikipedia 日本語版 API）

```
GET https://ja.wikipedia.org/w/api.php
  ?action=query&prop=pageprops&ppprop=wikibase_item
  &redirects=1&titles=<日本語名>|...&maxlag=5
```

- 50件ずつバッチ
- リダイレクトと表記正規化を吸収
- 失敗時は **simplify_name** でフォールバック（後述）

### Stage 2: 画像ファイル名取得（Wikidata SPARQL）

```sparql
SELECT ?item ?image WHERE {
  VALUES ?item { wd:Q1234 wd:Q5678 ... }
  ?item wdt:P18 ?image.
}
```

- エンドポイント: `https://query.wikidata.org/sparql`
- 100件ずつバッチ、1 req/sec
- `?image` は `Special:FilePath/<filename>` 形式 → ファイル名抽出

### Stage 3: ライセンス & サムネイル取得（Commons API）

```
GET https://commons.wikimedia.org/w/api.php
  ?action=query&prop=imageinfo
  &iiprop=url|extmetadata&iiurlwidth=400
  &titles=File:<filename>|...
```

- 50件ずつバッチ
- 400px 版の thumb URL を取得（Commons 側でリサイズ済み）
- `extmetadata` から license / artist / license_url を抽出

### フォールバック処理（A: 検索クエリ自動改善）

`simplify_name(name, category)` で以下の派生候補を生成し、第2ラウンドで再試行:

1. **カッコ以降を除去**: `西大寺会陽（はだか祭り）` → `西大寺会陽`
2. **ハイフン以降を除去**: `平泉-仏国土（浄土）を表す...` → `平泉`
3. **カテゴリ別曖昧性回避サフィックス**: `知床` → `知床 (世界遺産)`

カテゴリ別サフィックス:
- world_heritage: ` (世界遺産)`
- national_parks: ` (国立公園)`
- onsen: ` (温泉)`
- festivals: ` (祭)` / ` (祭り)`
- cuisine: ` (料理)`

### マナー対策

- User-Agent: `TravelExamApp/1.0 (...; learning tool)`
- HTTP 429/503 → 指数バックオフ（1, 2, 4, 8 秒）最大4回
- `maxlag=5` パラメータで Wikimedia サーバ負荷検知時に自動待機
- SPARQL は 1 req/sec、Commons は 0.5 req/sec

| **合計** | **774** | **すべて商用利用可** | — |

CC BY-SA は派生画像を再配布する場合のみ SA 制約が発動。**現状の Webアプリ表示用途では発動しない**（画像をそのまま hotlink するだけ）。

### ライセンス遵守チェック（UIで担保）

各画像の `<figcaption>` に必ず以下3要素を表示:
1. **撮影者名**（Commons の `Artist` フィールド、HTML除去・PDテンプレ整形済み）
2. **ライセンス名 + リンク**（例: `CC BY-SA 4.0` → `https://creativecommons.org/licenses/by-sa/4.0/`）
3. **元画像ページへのリンク**（Commons の File: ページ）

## 7. UI 統合状況

| 画面 | カテゴリ | 表示形式 |
|---|---|---|
| `lookup.html` 世界遺産タブ | world_heritage | 大型カード（左:画像 224×160、右:詳細） |
| `lookup.html` 国立公園タブ | national_parks | 大型カード |
| `lookup.html` 温泉タブ | onsen | コンパクトカードグリッド（タグ別グループ、薄ピンク） |
| `lookup.html` 祭りタブ | festivals | コンパクトカードグリッド（月別グループ、薄琥珀色） |
| `lookup.html` 郷土料理タブ | cuisine | コンパクトカードグリッド（カテゴリ別、薄ストーン色） |
| `map.html` 詳細パネル | world_heritage / national_parks / onsen / festivals / cuisine / **attractions** | `<figure>` 列（128×80サムネ＋クレジット） |

### 共通仕様

- **graceful degradation**: 画像取得失敗エントリは従来通り文字チップで表示（混在可）
- `loading="lazy"` で遅延読み込み
- `onerror="this.style.display='none'"` で 404 時に静かに非表示
- クレジット行は `truncate` + `title` 属性でホバー時に全文確認可

## 8. ファイル構成

```
webapp/public/images/
├── index.json              ← 目次（カテゴリ別 count と updated）
├── world_heritage.json     ← 24件 / 12.5 KB
├── national_parks.json     ← 34件 / 18.0 KB
├── onsen.json              ← 37件 / 19.7 KB
├── festivals.json          ← 30件 / 15.7 KB
├── cuisine.json            ← 72件 / 39.5 KB
└── attractions.json        ← 577件 / 319.2 KB（観光地は名前キー）

地理DB/scripts/
└── fetch_wikimedia_images.py  ← Python 標準ライブラリのみ
```

### スキーマ（カテゴリ別 JSON 共通）

```json
{
  "<id_or_name>": {
    "qid":          "Q15974",
    "thumb_url":    "https://upload.wikimedia.org/.../400px-Foo.jpg",
    "page_url":     "https://commons.wikimedia.org/wiki/File:Foo.jpg",
    "license":      "CC BY-SA 4.0",
    "license_url":  "https://creativecommons.org/licenses/by-sa/4.0",
    "author":       "User:Foo",
    "fetched_at":   "2026-05-02"
  }
}
```

`attractions.json` のみ `<id>` 部分が日本語名（観光地は ID 辞書を持たないため）。それ以外は YAML の `id` フィールドをキーとする。

## 9. 運用コマンド

### 単一カテゴリ取得（既存はスキップ、失敗のみ再試行）
```powershell
python 地理DB\scripts\fetch_wikimedia_images.py --category world_heritage
python 地理DB\scripts\fetch_wikimedia_images.py --category attractions
```

### 全カテゴリ一括
```powershell
python 地理DB\scripts\fetch_wikimedia_images.py --category all
```

### 既存も含めて全件再取得（リフレッシュ用）
```powershell
python 地理DB\scripts\fetch_wikimedia_images.py --category world_heritage --force
```

### 商用利用に関する注意

- 全画像は CC0 / Public domain / CC BY各種 / CC BY-SA各種 のいずれかで、**Webアプリ表示用途では商用利用可**
- ただし以下は守る必要あり:
  - 各画像のクレジット（撮影者・ライセンス・元URL）を表示する（実装済み）
  - 画像をそのまま販売・グッズ化しない（CC BY-SA の SA 縛り発動を回避）
  - クレジット表記をアプリのトーンに合わせて改変しない（撮影者名は Commons 表記をそのまま使う）
